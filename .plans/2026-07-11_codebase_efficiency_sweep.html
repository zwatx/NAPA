Verdict. Production architecture is fundamentally sound: capture is latest-frame, recording is bounded and asynchronous, benchmark decoding streams, and core geometry already caches important invariants. Fix the experimental lookup before treating that detector as usable, then address production NetworkTables/pose/telemetry costs in measured order.

Scope and method

The sweep covered all Python source under src/northstar_vision, the archived occlusion experiment, tests, packaging, CI, bundled profiles, and command workflows. Findings were accepted only when a concrete repeated operation, allocation, resource duplication, complexity problem, or measured workflow cost could be tied to exact code.

  • Static inspection of 9,707 source/test/config lines.
  • Three independent read-only sweeps: runtime, simulation/tooling, and tests/experiments.
  • Representative 198-frame cProfile simulation run.
  • Targeted tracemalloc/RSS measurement of the experimental decoder lookup.
  • Full tests, Ruff, coverage, import timing, CI/package review, and clean-diff checks.

“Every” here means every evidence-backed inefficiency found by those passes. Tiny unavoidable interpreter overhead and speculative micro-optimizations without a credible hot path were intentionally excluded.

Production/runtime remainder

  1. Batch corner undistortion: service.py:81-87 and solvers.py:457-476 make one OpenCV call per tag; one N×4 call removes transitions and small allocations.
  2. JSONL telemetry duplication: service.py:110,136 and recording.py:309-314 store the writer snapshot twice.
  3. JSONL byte counting: recording.py:257-264 encodes every record a second time only to measure it.
  4. Yaw buffer lists: orientation.py:52-74 rebuilds timestamps for insertion and estimation despite Python 3.11 keyed bisect support.
  5. Per-tag yaw matrix: solvers.py:491-498 repeats sin/cos and a matrix allocation for the same frame yaw.
  6. ROI dedupe: fiducials.py:59-87 is quadratic and recomputes centers; bounded by eight ROIs.
  7. Skip-scan invariants: prefilter.py:59-70 rebuilds its morphology kernel; gradient construction also creates several temporaries.
  8. Basis reconstruction: geometry.py:55-61 recreates a constant 4×4 transform for each pose.
  9. ID extraction: fiducials.py:55-56 creates a flatten copy and Python list before a tiny loop.
  10. Eager public imports: __init__.py:4-28 loads most of the vision stack for every command and import.

Simulation, benchmark, and artifact remainder

  1. Comparison rerender: simulation_cli.py:123-151 renders the same corpus three times.
  2. Identity effects: simulation_renderer.py:164-177 does two full-frame clips and a float32 conversion for clean images.
  3. Timing storage: benchmark.py:216,269-272 retains four boxed floats per evaluated frame; use a contiguous array for large runs.
  4. Duplicate sample storage: simulation_scoring.py:45-106 retains most metrics globally and per scenario.
  5. Durability barriers: simulation_artifacts.py:151-159 fsyncs each file; expensive on SD cards.
  6. Static renderer work: simulation_renderer.py:50-53,98-144 recomputes layout geometry, source corners, and marker masks.
  7. Double serialization: benchmark.py:450-452 and simulation_cli.py:158-164 encode file/stdout reports separately.
  8. Combined workflow imports: workflows.py:9-17 loads calibration and layout dependencies for either single-purpose command.

Experiment remainder

  1. Late erasure rejection: family.py:134-149 performs 2,348 allocating popcount comparisons before detector.py:199-217 rejects erased bits under the default policy.
  2. Quadratic dedupe: detector.py:140-167,518-540 repeatedly orders old quads and recomputes scale/centers.
  3. Repeated bit centers: family.py:22-24 rebuilds an invariant stacked array per candidate.
  4. Preprocess temporaries: detector.py:116-132 creates boolean, uint8, and multiply arrays where bitwise_not suffices; it also returns an unused binary image.

CI, packaging, and tests

  1. Duplicate CI: ci.yml:3-34 can run push and PR workflows for one commit, does not cancel stale runs, and repeats lint/coverage across four Pythons.
  2. Unused install surface: each compatibility cell installs .[dev,nt], pulling build/twine that only package-smoke uses.
  3. Port TOCTOU: test_nt_integration.py:18-30 releases a selected port before ntcore binds it.
  4. GUI OpenCV footprint: pyproject.toml:22-25 installs the roughly 119 MB GUI package on headless coprocessors; validate a headless/base split before changing it.
  5. Redundant simulation tests: test_simulation.py:69-120 runs the nine-frame suite three times; absolute cost remains small.
  6. Oversized fake frames: capture/orientation tests allocate 1280×720×3 arrays when assertions need tiny frames.
  7. Package-smoke dependency duplication: ci.yml:47-58 resolves/installs the heavy stack in separate wheel and sdist venvs; assurance value is real, so optimize only if CI minutes matter.

Efficient patterns to preserve

  • Latest-frame capture slot bounds latency and memory without copying frames.
  • Capture reconnect uses event waits and exponential backoff, not polling.
  • JSONL recording is off-thread, bounded, has explicit drop policy, timed waits, rotation, and bounded close.
  • Tag object points and marker images are cached; field-corner cache safely detects in-place layout mutation.
  • Replay benchmarks stream one decoded frame at a time, cap failure details, and stream integrity hashing in 1 MiB chunks.
  • The flat-frame minMaxLoc guard is a measured net win for blank frames and should stay.
  • SyntheticFrameSource repeats references rather than copying image buffers.
  • Profile parsing and strict validation are startup-only, not per-frame.

Recommended execution order

  1. Fix the experiment lookup and edge batching before further work on that detector.
  2. On production hardware, benchmark shared NT instance, generic-first pose fast path, and 1 Hz detailed health independently.
  3. Land the JSONL duplication and simulation identity/reuse changes; they are small and behavior-preserving with focused tests.
  4. Split CI lint/coverage and add cancellation.
  5. Address low-priority allocations only when target-device profiles show they matter.

Archived occlusion detector

The earlier memory fix replaced a 1.5-million-entry near-code dictionary with a 2,348-word scan. That made startup sane but made decoding the largest seeded-candidate cost: profiling 1,000 clean candidates attributed 0.870 of 1.530 seconds to decode_observed.

Multi-index result. Split each 36-bit word into three 12-bit blocks. Any word within Hamming distance two must match the query in at least one block, so three small hash lookups produce the only candidates that need exact comparison. A prototype verified 7,044 clean, one-error, and two-error queries across every tag rotation; the candidate count was p50 2, p95 4, max 8, and decode fell from about 238 µs to 0.98 µs (241×). The index allocated about 0.9 MB, and erased masks retain the current exhaustive fallback.

Other experiment-only measurements are useful if this archived detector is revived: a half-resolution candidate pyramid cut preliminary 1080p runs from 5.2–6.7 ms to 3.2–4.0 ms; seeded prior corners cut one clean 1080p frame from 5.28 ms to 0.66 ms; and cv2.remap reduced an 80×31 edge sample from 79.7 µs to 10.5 µs. None should ship without the missing scale, blur, clutter, perspective, boundary, and occlusion corpus.

Benchmark work required first

  1. Capture a real sequential Raspberry Pi corpus. The checked-in example manifest has no images, while the synthetic suites repeat only 9 or 31 scenes. Record tag pixel-size bins, ordered corners, camera/pose truth where practical, and camera/CPU metadata.
  2. Add acquisition and recovery events. Include cold start, tags entering/leaving, fast pan, complete occlusion, camera cuts, dropped frames, and explicit detector resets so temporal algorithms cannot inherit state across repetitions.
  3. Make A/B order fair. Alternate or randomize baseline/candidate order across at least five fresh processes, report per-process deltas, and test both the OpenCV 4.7 floor and deployed Pi build.
  4. Tighten non-inferiority gates. Require per-size/per-condition recall, corner RMS, pose translation/rotation, and reacquisition bounds; equal aggregate detection counts can hide a small-tag regression.

Reproduction record

The detector prototypes ran through run_simulation with seed 2026, one reused rendered corpus, 30 measured repetitions, and 3 warmup passes per candidate. ArUco3 used useAruco3Detection=True with its default minimum-length ratio of 0.0. The restricted-dictionary prototype used original IDs 1–22 and remapped each returned row through that tuple; it modeled a field-sized dictionary but was not a deployed layout. The exact aggregate inputs and outputs are embedded in this file as measurement-data.

The multi-index prototype exercised every family tag and rotation with clean, deterministic one-bit, and deterministic two-bit corruption (7,044 queries), then timed 2,000 sampled queries across five timeit repeats and recorded the best run. The 932,792-byte index figure is a tracemalloc snapshot delta. Prototype scripts and raw per-frame samples were not persisted, which is why the first action is to add supported A/B routes rather than promote either candidate directly.

Sources and boundaries

  • OpenCV DetectorParameters documents ArUco3, minimum marker ratio, threshold windows, and AprilTag decimation.
  • Romero-Ramirez et al., Speeded up detection of squared fiducial markers describes the multi-scale and temporal ideas behind ArUco3.
  • Norouzi et al., Fast Search in Hamming Space with Multi-Index Hashing provides the exact binary-search technique adapted to tag decoding.
  • Bouguet, Pyramidal Lucas–Kanade is the basis for the temporal-corner research path.
  • AprilRobotics AprilTag 3 and the ArUco Nano paper are backend research references, not current dependency recommendations.

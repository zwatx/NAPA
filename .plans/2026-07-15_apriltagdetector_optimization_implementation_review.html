The recommended hardware-independent optimizations are implemented behind explicit comparison gates, with the production detector unchanged and Raspberry Pi validation deliberately left open.

Context

The optimization follow-up identified ArUco3, a field-layout-only dictionary, and compact multi-index decoding as the strongest candidates that could be implemented and verified without camera or Raspberry Pi hardware. This review covers the implementation for issues #40, #41, and #42; physical-corpus and threshold-window work in #43 and #44 remains out of scope.

Recommendation

Keep ArUco3 and layout-restricted decoding as opt-in simulation and replay candidates until physical hardware exists. Ship the compact experimental decoder index now because its exact fast-path domain is explicit and every unsupported mask or Hamming limit falls back to exhaustive decoding.

Implementation reviewed

  1. fiducials.py now constructs baseline, ArUco3, and layout-restricted detectors. Restricted dictionary rows are mapped back to sorted original tag IDs, so compact OpenCV row numbers never escape as observations.
  2. simulation_cli.py adds both candidates to the existing opt-in comparison run and reuses the baseline's generated corpus. benchmark.py adds an opt-in replay comparison over one decoded-frame cache and labels the frame source and retained cache bytes.
  3. The experimental tag36h11 decoder indexes three disjoint 12-bit blocks. Full-mask observations with max_hamming <= 2 use the ordered candidate union; erased masks and larger limits retain the exhaustive path.

Risks & mitigations

Replay fairness increases comparison memory with a decoded image cachemediumThe path is opt-in, reports cached_decoded_image_bytes, and rejects caches beyond a configurable 256 MiB default ceiling.
The compact index could change tie or rotation semanticslowCandidate indices are sorted in exhaustive iteration order, and equivalence tests cover all tag rotations plus corruption and fallback cases.

Verification

  • .venv/bin/python -m pytest -q: 131 passed.
  • .venv/bin/python -m pytest -q experiments/occlusion_detector/tests: 6 passed.
  • .venv/bin/ruff check src tests and git diff --check: passed.
  • Regression tests cover cache-limit rejection and exact-zero comparison metrics, which serialize as null instead of raising division errors.
  • The standard nine-frame synthetic comparison preserved 28/28 true positives, zero false positives, and zero false negatives for baseline, ArUco3, and layout-restricted detection. ArUco3 measured 1.56x processing p50 speedup and the restricted dictionary measured 1.78x on this desktop run.
  • The generated-corpus replay comparison also preserved exact accuracy and confirmed shared decoded frames, original ID remapping, unchanged production defaults, and explicit physical-validation metadata.

Remaining validation

  • No Raspberry Pi or physical camera was available, so neither detector candidate is approved as the production default.
  • Issue #43 should add sequential reacquisition and tag-size coverage before temporal or coarse-to-fine algorithms are considered.
  • Issue #44 should evaluate threshold-pass reduction only after a representative physical image corpus exists.

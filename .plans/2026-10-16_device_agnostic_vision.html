Make image processing reusable across hosts first. Keep camera SDKs and transports outside the algorithm; share a native implementation when crossing language runtimes.

Decision

The reusable seam is a synchronous call from an image to structured observations. Each host supplies its own pixels, timestamps, calibration, and scheduling. A headset, a desktop, and a Raspberry Pi are consumers of the same interface. There is no fixed four-camera topology.

Implemented in this change: a transport-free Python VisionProcessor, a structural detector interface, geometry-only solver inputs, and delegation from the existing camera service. Not implemented: a native C ABI, C# bindings, target SDK adapters, or an adaptive scanning algorithm. This is a concrete first phase of portability, not a claim that Python now runs inside every host.

Detection requires no calibration, field layout, robot profile, rig mount, yaw source, camera ID, network connection, or device SDK. The processor imports no capture, profile, recording, or output modules. OpenCV and NumPy remain implementation dependencies of this Python phase.

Image and result contract

  • Current images are nonempty uint8 grayscale, BGR, or BGRA NumPy arrays. Strided arrays work. Hosts convert RGB, YUV, GPU textures, and rotated frames before calling; conversion and readback costs belong in end-to-end measurements.
  • The call borrows the image synchronously and does not retain it. Detector adapters must not mutate or retain it and must return independent corner arrays. Calls must not overlap on one processor.
  • Results retain original tag IDs and finite 4×2 corners in input pixel coordinates. A replacement detector must preserve the existing corner order after decoded rotation, rather than silently reusing a different tag convention.
  • Calibration includes intrinsics, distortion, and image resolution. Resizing, rotating, or cropping pixels requires corresponding intrinsics. Calibrated processing rejects mismatched resolution.
  • The physical tag size is in metres. IPPE vectors use OpenCV axes; existing field and rig outputs use WPILib axes. Host/world coordinate conversion is explicit and remains outside the detector.
  • Frame timestamps and optional capture clock values are caller-supplied seconds. The processor never computes frame age from a different device clock. The FRC service resolves yaw after image processing so samples delivered during detection can bracket capture time.
  • No tags is a successful empty result. Invalid input and backend failures raise to the Python caller. A future native interface must represent errors explicitly without exceptions crossing languages.

Should finer rakes be implemented?

Keep them experimental and deferred. The current prefilter already performs sparse sampling followed by full-resolution detection inside padded regions. A second or third sparse level is useful only when it removes enough work to repay its own overhead. It cannot recover a small tag discarded at the first level.

The existing historical desktop comparison recorded tagged frames at 2.51 ms with skip-scan versus 2.29 ms for full-frame detection, and blank frames at 0.083 ms versus 0.050 ms with the uniformity gate. These are the July repository measurements, not fresh target-device benchmarks. They support leaving the prefilter off by default and do not verify the earlier 14.5×/2× claims for this pipeline.

When added, a bounded adaptive-search detector should remain interchangeable at the same seam. Compare it with baseline, ArUco3, and the existing prefilter using identical recorded frames. Require stable IDs/corners and no recall regression at the minimum supported tag size; include blur, occlusion, perspective, low contrast, image borders, and positions between sampling lines. Use padded overlaps and a defined full-frame reacquisition policy, cap levels and ROI coverage, and measure p50/p95 processing and frame age on the actual host.

The compact custom decoder remains in the archived experiment. It indexes three 12-bit payload blocks across all rotations, checks exact Hamming distance on candidates, and uses exhaustive decoding for erased masks or limits above two errors. Moving that implementation into a shared core must preserve rotation/corner semantics and fallback behavior; this refactor does not promote it into the main pipeline.

Cross-language portability: next phase

Use one C/C++ implementation with a small versioned C ABI, then thin Python and C# bindings. C# native interop supports C-style interfaces; it does not consume Python classes or NumPy memory conventions automatically. This recommendation is supported by Microsoft's ABI guidance and P/Invoke documentation. Unity also documents native plug-ins; no Unity dependency belongs in the core.

  1. Freeze portable data contracts. Define image pointer, width, height, byte row stride, pixel-format enum, borrowed-buffer lifetime, capture timestamp, numeric intrinsics, and explicit distortion model. Define IDs/corners and optional metric poses with fixed conventions. Avoid strings, device handles, and managed objects in the per-frame interface.
  2. Build one native detector. Begin with the maintained detector backend and port the custom candidate/decoder path behind the same interface as a separately tested option. Keep Python as the reference until differential tests pass. Put prefiltering and candidate refinement inside this module so bindings never reimplement them.
  3. Expose lifecycle and bounded results. Use create/process/destroy operations with an opaque instance handle, ABI/version discovery, explicit status codes, and caller-owned result capacity plus required-count reporting. Define overflow and stale-result behavior. Keep errors and allocations within the owning runtime.
  4. Add thin bindings. Python validates buffers and releases them after synchronous calls; C# pins/copies input for the duration of the call and materializes results before reuse. Camera permission and SDK access remain independent adapters. CPU architecture and OS builds are packaging concerns.
  5. Verify shared behavior. Run identical fixtures through reference Python, native, and C# paths on desktop first, then on representative ARM64 hosts. Exercise strided buffers, bad sizes, lifetimes, all rotations, correction limits, invalid words, erasures, ID remapping, empty frames, coordinate conversions, and per-camera isolation. No target is declared supported before its build and runtime checks pass.

Verification and remaining work

  
The original production suite and new embedding tests pass: 146 tests with 80.71% coverage. Fifteen new cases cover raw and strided color inputs, a structural backend, known calibrated geometry, layout isolation and yaw-sample arrival during detection, timestamp validation, resolution mismatch, backend failures, and import independence. The six custom experimental decoder tests pass. Ruff format/check and diff whitespace checks pass.

  
Build/package validation and independent final review are recorded in the companion review after completion. No headset, camera hardware, native toolchain, or C# runtime has been validated by this change. The native port and adaptive search are future work; the service and Python embedding seam share the same processing implementation today.
